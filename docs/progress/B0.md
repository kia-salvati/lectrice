# B0: workspace skeleton (done 2026-10-23)

## What was built
- `backend/` Cargo workspace (resolver 3, edition 2024): `crates/lectrice-{domain,infra,app,api}`.
  All later dependencies are pinned exactly in `[workspace.dependencies]` and already added to the
  crate that will use them. `rustfmt.toml` uses `max_width = 160` (the rules' "one line per call").
- **Toolchain proven:** `cargo build` downloads and compiles sherpa-onnx 1.13.8 (static prebuilt)
  and pdfium-render 0.9.4. A throwaway example (deleted afterwards) linked both, ran
  `OfflineTts::create` and bound `vendor/pdfium/lib/libpdfium.so`.
- **domain** (`lectrice-domain/src/`):
  - `error.rs`: the §8 registry (generated by one macro: `ErrorName`, `ErrorName::ALL`, `as_str`,
    `spec() -> ErrorSpec { code, status, operational, description }`), and `AppError` (one or
    more raised names, the first is primary, an internal `detail`, and a `source` chain). Also
    `AppResult<T>`.
  - `ids.rs` (`DocumentId` accepts only 64-hex sha256, so it is safe as a directory name;
    `SentenceId`, `BlockId`, `VoiceId`, `ExportId`), `document.rs` (Document, Block, BlockKind with
    `is_spoken_by_default` + `cue_text`, Sentence, PageLabel, DocumentMeta, ReadingPosition,
    DocumentSummary), `speech.rs` (Voice, SpeechRequest, Audio, AudioKey), `export.rs`
    (AudioExport, ExportFormat, ExportStatus, ExportTarget, ExportedFile), `paging.rs`
    (ListOptions, Page), `clock.rs` (Timestamp, Clock), `pdf.rs` (PdfContent, PdfPage, TextRun,
    BoundingBox, OutlineItem), `cleaned.rs` (CleanedDocument, CleanedBlock, TextSpan).
  - `ports.rs`: every trait: PdfTextSource, DocumentCleaner, SentenceSplitter, SpeechEngine,
    AudioEncoder, DocumentReader, DocumentWriter, AudioCache, AudioExporter + ExportWriter.
- **infra:** `SystemClock` (whole seconds); empty stubs `speech/`, `pdf/`, `text/`, `storage/`, `export/`.
- **app:** `RequestContext { request_id }`, the `UseCase` trait (`NAME`, `run(&ctx, args)`);
  empty stubs `documents/`, `speech/`, `exports/`.
- **api:** `config/` (TOML → `LECTRICE_<SECTION>_<KEY>` overrides typed like the file value →
  `~` and relative-path resolution against the config file's folder → validation),
  `logging.rs` (JSON lines, `RUST_LOG`, request span with method/path/request id only),
  `error.rs` (`ApiError(AppError)` → `{ error: { name, code, message } }`, message always the
  registry text; detail + cause chain only in the log, `warn` if operational, else `error`),
  `context.rs` (`Ctx` extractor → `RequestContext` from `x-request-id`), `app.rs` (router +
  request-id, trace and CORS layers), `routes/health.rs` (`GET /api/health`), `shutdown.rs`
  (SIGINT/SIGTERM), `server.rs` (binds 127.0.0.1), `state.rs`, `main.rs`.
- `backend/config.toml` (spec §11 defaults), `backend/vendor/pdfium/` (chromium/7881:
  `lib/libpdfium.so`, `LICENSE`, `licenses/`, `VERSION`), `backend/README.md`.

Notes for the steps:
- Services implement `lectrice_app::UseCase`, raise `AppError::new(ErrorName::X)` and never call
  `.spec()`. Log with `tracing::info!(service = Self::NAME, doc_id = %id, blocks = n, "message")`:
  flat fields, ids/counts/durations only, never book text.
- `Sentence.speech_text` (B2/B3): the text to speak when it differs from the shown text (from
  `TextSpan { spoken: false }`); `Sentence::spoken_text()` picks it.
- `SentenceSplitter::split` returns byte ranges into the text, so B3 can map sentences back onto
  spans for `pageIndex` and speech text.
- `sha2` is 0.11 (digest 0.11 API). Bumping `DocumentCleaner::version` triggers re-cleaning from
  `find_original_pdf`.

## Deviations from the spec, and why
1. **Domain depends on `serde` and `chrono`**, not only `thiserror` (§2). The saved
   `document.json` (§5) and the wire shapes are the same, so domain entities derive serde with
   camelCase and are both stored (infra) and sent (api). API-only envelopes (health, import
   result, error body, `Document + lastSentenceId`) are api presenters. `regex` and
   `unicode-normalization` are in domain for B2's pure rules. `thiserror` is only used in api
   (`ConfigError`); `AppError` implements `Error` by hand.
2. **Traits got what the use cases need** (§3 listed less): `DocumentCleaner::version`;
   `DocumentReader::find_summary` (GetDocument needs `lastSentenceId`, ImportPdf returns a summary)
   and `find_original_pdf` (re-cleaning); `DocumentWriter::save` takes a `DocumentMeta` and there is
   `mark_opened` (touching `lastOpenedAt`); `SentenceSplitter` returns byte ranges instead of
   strings; a `Clock` port so services are testable. All traits are `Send + Sync`.
3. **`SpeechRequest` has no speed** (CLAUDE.md says "text + voice + speed"): §4 fixes audio at 1×
   and the player applies the speed, so a speed field would only invite cache misses.
4. **`Sentence.speechText` is new** (optional, omitted when equal to `text`): needed for the
   survey's speech-only filters (citations, URLs). The frontend ignores it.
5. **`AudioExporter`** is `begin(target, sample_rate) → ExportWriter { start_chapter, append,
   finish }` (streamed, so a book never sits in memory). B6 may refine it.
6. **Server binds 127.0.0.1 only** (no host key in §11): it is a local app.
7. **tokio 1.53.3**, not the latest: 1.54.0 was yanked and 1.54.1 was two days old.
8. Config validation also requires `keep_minutes_per_document ≥ read_ahead_minutes` (otherwise
   the cache would evict read-ahead audio straight away). Unknown or mistyped `LECTRICE_*`
   overrides fail at startup, which catches typos.
