# B6: whole-book audio export, MP3 + M4B (done 2026-10-23)

## What was built
- **infra `FfmpegExporter`** (`lectrice-infra/src/export/`): spawns `ffmpeg` and pipes 24 kHz mono s16le PCM to stdin.
  - MP3: `libmp3lame`, 64 kbps, mono, ID3v2.3 tags (title, artist = voice name, album, genre Audiobook).
  - M4B: pass 1 encodes AAC 64 kbps mono into a partial mp4. At `finish`, a short second pass
    (`-c copy -f ipod -movflags +faststart`) adds an ffmetadata file with the tags and **chapter marks** built from the
    sample positions where `start_chapter` was called (`ffmetadata.rs`, escaped, empty chapters dropped, audio before
    the first mark becomes a chapter named after the book).
  - Everything is written to `.partial-*` files in `exports/<docId>/`, then renamed to `<voiceId>.<ext>`. Dropping a
    writer without `finish` (cancel, error, shutdown) kills ffmpeg, and the partial files are deleted. At startup
    `remove_partial_files` sweeps whatever a crash left behind. If the program is missing, you get `ExporterUnavailable`
    (from `check_available` and from `begin`). ffmpeg's stderr goes to a temp file, and its tail is put in the error detail.
- **infra** `WavDecoder` (reads cached clips back into PCM) and `FsExportRecordStore` (`exports/jobs/<exportId>.json`,
  atomic writes). `safe_component` moved from `audio_cache.rs` to `storage/path_component.rs` so both can use it.
- **app `exports/`**:
  - `plan.rs` (pure): the playback order (`playback_order`, so `readSkipped` and cues work exactly like the player),
    with a chapter mark before each heading of level ≤ 2. `max_sentences` keeps only the first sentences.
  - `run.rs`: one export. It keeps a window of 4 sentences ahead. Each one is a cached clip (`AudioCache::get` +
    decode) or a `submit_with` at `SpeechPriority::Export`, delivered over a channel. The waits poll the cancel flag every
    200 ms, so a cancel never waits on the engine. Dropping a pending sentence withdraws it from the worker. **Fresh
    audio goes straight to the encoder and is never put in the cache.** Sentences with empty speech text add no audio.
    The writer opens lazily on the first clip, so its sample rate comes from the audio.
  - `progress.rs` (pure): `estimatedSecondsLeft` = remaining spoken characters × elapsed ÷ done characters
    (`null` until something was spoken, `0` when done), and 5 % checkpoints.
  - `jobs.rs`: the `ExportJobs` registry, with one `export-runner` thread that runs queued jobs one at a time (FIFO).
    The states are `queued → running → done | failed | cancelled` and `queued → cancelled`. Status changes and
    every 5 % checkpoint are saved to disk. On start, records that were `queued`/`running` become `failed`.
    When a job finishes, older `done` jobs for the same document + voice + format are deleted (their file was
    replaced). Dropping the registry (server shutdown) abandons the running export and saves it as `failed`.
  - Use cases: `StartAudioExport` (checks the voice, then the document, then the exporter, so a bad request never makes
    a job; returns the queued or running job if one exists for the same document + voice + format),
    `GetAudioExport`, `ListAudioExports` (newest first, `DocumentNotFound` for unknown docs), `CancelAudioExport`
    (finished jobs stay as they are) and `GetAudioExportFile` (`ExportNotReady` unless done).
- **api** (`routes/exports.rs`):
  - `POST /api/documents/{id}/exports` → 202 `{ export }`. The body DTO is `voiceId` (not empty), `format` (`mp3`/`m4b`,
    trimmed, case-insensitive, otherwise `ExportFormatUnsupported`) and an optional `readSkipped` (default false).
    Unknown fields give `RequestInvalid`.
  - `GET /api/documents/{id}/exports` → `{ items }`. `GET /api/exports/{id}` → `{ export }`. `DELETE /api/exports/{id}` → 204.
  - `GET /api/exports/{id}/file` is streamed in 64 KB chunks (it never sits in memory). It sends `Content-Type`
    `audio/mpeg` / `audio/mp4`, `Content-Length`, and
    `Content-Disposition: attachment; filename="<Title> (<Voice>).mp3"; filename*=UTF-8''…`. Characters that are
    unsafe in file names are replaced, and non-ASCII names are kept in `filename*`.
  - Without a speech engine, all export routes give 503 `SpeechEngineUnavailable` (`AppState.exports` is `None`).
- **Config** `[export] ffmpeg = "ffmpeg"`, `max_sentences = 0` (0 = whole book, `LECTRICE_EXPORT_MAX_SENTENCES=60` for
  quick tests). The startup log says whether the exporter is ready, and how many partial files were removed.

## Manual check (debug build, scratch data dir, port 7981, 8 threads, `max_sentences=60`, read-ahead 1 min)
- Imported DDS (2402 sentences). An export covers 60 sentences: 35 spoken, 25 empty (URL-only front matter), 7 chapter marks.
- **MP3**: 202 → done in **58.4 s** while I also played audio (below). `ffprobe`: mp3, 24000 Hz, mono, 64 kbps,
  **185.2 s**, 1.48 MB, title "Designing Distributed Systems", artist "Heart". The download had the right
  `Content-Type`/`Length`/`Disposition` and was byte-identical to the file.
- **M4B**: done in **39.9 s** (4.6× real time). `ffprobe`: aac, 24000 Hz, mono, ≈ 74 kbps total, **185.1 s**, 1.70 MB,
  **8 chapters** (the book-title lead-in, the two title-page headings, Preface, Who Should Read This Book, Why I Wrote
  This Book, The World of Distributed Systems Today, Navigating This Book), with title and artist tags.
  The sample is saved as `docs/progress/B6-sample.m4b` (`xdg-open docs/progress/B6-sample.m4b`).
- **Playback during an export:** with the export at 42/60, sentence 500 (6.4 s of audio) came back in **2.10 s**,
  then 501 in 0.86 s and 900 (a jump) in 2.39 s. When idle, a 5.1 s sentence took 1.02 s. So playback waited for
  at most the one export sentence already running (about 0.7 s), then went first. After those requests, the
  1-minute read-ahead ran ahead of the export, so the export paused for about 20 s (12:28:50 → 12:29:10) and then went on.
- **Reuse:** I played sentence 31, which cached 31–41 through read-ahead. A new MP3 export then logged `cached: 11`.
- **Cancel** at 42/60 → 204, then `GET` showed `cancelled`. Both partial files were gone, no ffmpeg was running, and the
  earlier `af_heart.mp3` was untouched.
- **Crash:** I killed the server with `kill -9` during an M4B export (30/60). On restart the log said
  `removed_partial_files: 2` and `interrupted: 1`, and the list (newest first) showed failed 30/60, cancelled 42/60,
  done, done. **SIGTERM** during an export logged "export interrupted by shutdown", saved it as `failed`, and the
  server exited cleanly with no ffmpeg left.
- Progress was logged every 5 %, with ids and counts only and no text. Note that runs of silent sentences log
  several 5 % steps in the same millisecond.

## Contract vs the frontend (`src/api/exports.ts`, `src/types/api.ts`, `src/hooks/useAudioExport.ts`)
Paths, methods, body fields (`voiceId`, `format`, `readSkipped`), the `{ export }` / `{ items }` envelopes, every
`AudioExport` field, the status names and the HTTP codes all match. Notes:
1. **`RequestInvalid` is still missing from the frontend's `ApiErrorName`** (open since B4). A bad export body gives it.
2. Starting an export while one for the same document + voice + format is queued or running returns **that job**
   (still 202) instead of a second one. The hook just shows it.
3. `sentencesTotal` counts every sentence in playback order, empty ones included, the same as the mock's
   `buildPlaybackOrder` count.
4. With the speech engine down, `GET …/exports` gives 503 `SpeechEngineUnavailable`, so the export panel shows an
   error. The player is unusable then anyway.
5. The frontend's `<a download>` name and the backend's `Content-Disposition` use the same `<Title> (<Voice>).<ext>`
   format. Characters that are unsafe in file names are replaced, so the two names may differ slightly; browsers
   use the header's name.

## Deviations
1. **Domain contract changes** (B0 said B6 may refine them): `ExportTarget` gained `title` and `artist`.
   `AudioExporter` gained `check_available()`, so a missing ffmpeg is a 503 at POST and not a job failing later.
   New ports `AudioDecoder` (to reuse cached WAV clips) and `ExportRecordStore` (job metadata on disk). New
   `ExportRecord`, `ExportFormat::{ALL, extension, from_extension}` and `ExportStatus::is_active`.
2. **Dependencies:** the tokio `fs` feature and `futures-core =0.3.34` (already in the lock through axum) to stream the
   download. No new crates were downloaded.
3. **New config section `[export]`** (`ffmpeg`, `max_sentences`), not in spec §11. `max_sentences` is the
   short-range option for manual checks.
4. Exports run **one at a time** (FIFO). One job per document + voice + format can be active, because they share one
   output path (spec §6). An older finished job for the same file is deleted from the list once a newer one finishes.
5. Jobs that were **queued** (not only running) at a crash or shutdown also become `failed`. They are not resumed.
6. A cancel that lands during the final rename keeps the job `cancelled`, but the new file may already have replaced
   the old one (a sub-second window).
7. Chapter marks use heading levels ≤ 2 (DDS: 38 marks for the book instead of 144 with every level).
   Sentences with nothing to say add no audio (playback plays 0.25 s of silence for them).
8. Export files are created with mode 0600 (tempfile's default), like the rest of the data dir's temp-then-rename writes.
