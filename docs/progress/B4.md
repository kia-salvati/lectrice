# B4: HTTP API and speech worker (done 2026-10-23)

## What was built
- **Routes** (`lectrice-api/src/routes/`). Each feature file holds its input DTOs with validation, its
  presenters and thin controllers. Every service runs through `run_blocking` (`spawn_blocking`).
  - `GET /api/health`: `speechEngine` is now real (`ready` when the engine loaded).
  - `GET /api/voices` → `{ voices, defaultVoiceId }`. Returns 503 `SpeechEngineUnavailable` if the engine failed.
  - `POST /api/documents`: multipart field `file`. The controller counts **every** part's bytes against
    `upload.max_mb` (axum's default body limit is off on that route) and stops reading at the limit
    (`UploadTooLarge`). A missing `file` part, a body that isn't multipart or a broken multipart gives
    `UploadMissingFile`. The response is 201 `{ document, alreadyInLibrary: false }` or 200 with `true`.
  - `GET /api/documents?limit&offset` → `{ items, total, limit, offset }`. `limit` must be 1–100;
    unknown or mistyped params give `RequestInvalid`.
  - `GET /api/documents/{id}` → the §5 document plus `lastSentenceId` (always present, `null` if unread).
  - `PUT /api/documents/{id}/position` with `{ sentenceId }` → 204.
  - `GET /api/documents/{id}/sentences/{sentenceId}/audio?voice=…&rate=…&readSkipped=…`. `voice` is required;
    `rate` is optional (default 1) and must be 0.75–2 (NaN is rejected); `readSkipped` is optional (default false).
    The `Content-Type` comes from the encoder (`audio/wav`).
  - A malformed document id gives `DocumentNotFound` and a non-numeric sentence id gives `SentenceNotFound`.
    Bad query or JSON input gives `RequestInvalid` (see deviation 1).
- **app `speech/`**:
  - `ListVoices` returns the engine's voices plus the configured default voice.
  - `SpeakSentence`: check the voice against `engine.voices()` (`VoiceUnknown`), then load the document
    (`DocumentNotFound`), find the sentence or cue (`SentenceNotFound`) and build the `AudioKey` (doc, cleaner
    version, engine id, voice, sentence). Next: cache `get`, then on a miss submit to the worker at `Now`,
    encode, cache `put` and return the bytes and mime type. It speaks `Sentence::spoken_text()`, so `speechText`
    is used when present.
    **Empty speech text (e.g. a URL-only sentence) returns 0.25 s of silent WAV** without calling the engine or
    the cache. I picked silence over an error so the player just moves on. A failed cache `put` is logged as a
    `warn` and the audio is still returned. A failed `get` fails the request (`StorageFailed`).
    `rate` and `readSkipped` are in the args and logged; B5 uses them for read-ahead.
  - **`SpeechWorker`** (`speech/worker.rs`): see the API below.
- **infra `FsAudioCache`** (`storage/audio_cache.rs`): `<data_dir>/audio/<docId>/c<cleanerVersion>/<engineId>/<voiceId>/<sentenceId>.wav`.
  It uses atomic writes (B3's `write_atomically`) and has no eviction yet (B5). Engine and voice ids must be plain
  names (`[A-Za-z0-9._-]`, not only dots), otherwise it raises `StorageFailed`.
- **Composition root** (`lectrice-api/src/composition.rs`):
  - `build_state(&Config)` builds the real adapters. `assemble(Adapters, Settings)` wires them into services
    (tests call it with fakes).
  - `build_speech_engine(&SpeechConfig)` is the engine factory (`speech.engine` → adapter). It was moved out of
    `dev_speak.rs`, which now calls it.
  - If the engine fails to load, that is logged as a `warn` and health reports `failed`. Anything else that fails
    stops the start: pdfium not loadable, or `speech.default_voice` not a voice of the engine (`VoiceUnknown`).
  - `upload.max_mb` is converted to bytes (MiB, saturating) for both the route and `ImportPdf::new`.
- `main.rs` serves `composition::build_state(&config)`. `AppState` is now
  `{ documents: Arc<DocumentServices>, speech: Option<Arc<SpeechServices>>, upload_max_bytes }`.

## Speech worker API (for B5/B6), `lectrice_app::speech`
```rust
let worker = SpeechWorker::start(engine)?;                     // one thread named "speech-worker" owns synthesis
let job = SpeechJob { key: AudioKey, request: SpeechRequest, priority: SpeechPriority::ReadAhead };
let ticket: SpeechTicket = worker.submit(job);                 // blocking: ticket.wait() -> AppResult<Arc<Audio>>
let cancel: CancelHandle = ticket.cancel_handle();
let cancel = worker.submit_with(job, |outcome: SpeechOutcome| { /* runs on the worker thread */ });
cancel.cancel();                                               // true if withdrawn before delivery
```
- Priority order: `Now` > `ReadAhead` > `Export`. Within a priority, jobs run first in, first out.
- **Merging:** a job whose `AudioKey` is already queued or running joins it. The engine runs once and every waiter
  gets the same `Arc<Audio>`. A merge with a higher priority moves a queued job up. On an error, the first waiter
  gets the original error (with its source chain) and the others get a copy (names + detail).
- **Cancel** withdraws one waiter. A queued job with no waiters left is dropped and never synthesized. A running
  job can't be stopped (the engine call is synchronous); only that waiter's result is dropped. A cancelled
  ticket's `wait()` returns `Internal`.
- `submit_with` callbacks run on the worker thread. Keep them short (e.g. encode + cache put for read-ahead) and
  **never wait on another speech job inside one** (it would deadlock). Submitting without waiting is fine.
- An engine panic fails only that job (`SpeechSynthesisFailed`); the worker keeps running.
- Dropping the last `Arc<SpeechWorker>` stops the thread after the running job. Queued tickets then return an error.
- Built on `std` only (Mutex + Condvar + mpsc, no tokio in app). `wait()` blocks, so call it on the blocking pool
  (routes do) or on your own thread (export).
- The worker logs one line per job: `{ docId, sentenceId, voiceId, priority, audioSeconds, synthMs, waiters }`.
  The service logs entry, cache hit/miss, wait time, encode and the cache write. No text is logged.

## Contract vs the frontend brief
Paths, query names (`voice`, `rate`, `readSkipped`), JSON field names and status codes match the brief's
`src/api/*` and `src/types/*`. Differences:
1. **New error `RequestInvalid`** (1000, 400): the brief's `API_ERROR_NAMES` doesn't know it, so the client maps it
   to `Internal`. W should add it to `ApiErrorName`. The client never sends invalid params, so it only affects curl
   and bugs.
2. `Sentence.speechText` appears in document JSON (from B0/B3). The frontend ignores it.
3. `voice` is required on the audio route (the brief always sends it).

## Deviations and notes
1. **Registry change:** added `RequestInvalid => (1000, 400, operational, "This request isn't valid.")`. Spec §8 has
   no name for a malformed query or body (bad `rate`, `readSkipped`, `limit`, a position body without `sentenceId`).
   Without it, axum's plain-text rejections would break the `{ error }` shape. Spec §8 and the frontend
   `ApiErrorName` should list it.
2. `SpeakSentence` parses the whole `document.json` on every request (435 KB for DDS, a few ms). If B5's read-ahead
   makes this hot, add a small in-memory cache of the last document.
3. `AppState` no longer implements `Default` (it needs real services), so `app.rs`'s tests now use `test_support::TestApp`.
4. Cache `put` errors don't fail playback (warn only); `get` errors do.
5. The upload limit is enforced by our controller, not `DefaultBodyLimit`, so the 413 has the registry body.
